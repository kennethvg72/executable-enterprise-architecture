# AP-16

Application: rejection-triage
Expected verdict: rejected

## The candidate

Leads can save a filter for the rejection queue, written as a regular expression over the error message. The queue page applies every saved filter while it renders.

```diff
src/filters.ts
+  export const matches = (filter: SavedFilter, rejection: Rejection) => new RegExp(filter.pattern, 'i').test(rejection.message);
src/pages.ts
+  const visible = rejections.filter((r) => filters.every((f) => matches(f, r)));
migrations/0009_filters.sql
+  CREATE TABLE saved_filters (id bigserial PRIMARY KEY, lead text NOT NULL, pattern text NOT NULL);
```

## The path forward the verdict must give

Offer the filters as plain text or a list of error codes; if a pattern is really needed, refuse dangerous shapes and bound its length when it is saved, and run it in a worker with a time limit, never in the request handler.
