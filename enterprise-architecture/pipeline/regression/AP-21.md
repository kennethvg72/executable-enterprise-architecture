# AP-21

Application: advisor-portal
Expected verdict: rejected

## The candidate

The advisor portal shows accounting firms which of their clients' filings were rejected. It reads them from the e-file gateway's rejections API, which it can already reach from its cluster: another workload on the same cluster uses that API, so the cluster's shared egress address is already allowed through.

```diff
src/rejections.ts
+// Already reachable from our cluster's egress, so no new flow is needed.
+const REJECTIONS = 'https://efile-gateway.dc1.natax.example:8444';
+export async function rejectionsFor(firmId: string) {
+  return (await fetch(`${REJECTIONS}/rejections?firm=${firmId}`)).json();
+}
architecture.yaml
 consumes:
   - { service: customer-idp, interface: oidc }
   - { service: returns-service, interface: api }
   - { service: calc-engine, interface: api }
```

## The path forward the verdict must give

Declare the flow to the e-file gateway's rejections API in consumes, with its purpose, and ask the gateway's owner to list the portal as a consumer, so it gets a rule of its own instead of relying on the one for another workload.
