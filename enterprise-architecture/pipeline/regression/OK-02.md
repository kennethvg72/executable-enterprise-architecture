# OK-02: Hidden for convenience, authorized on the server

Application: rejection-triage
Expected verdict: approved
Counterpart of: AP-01

## The candidate

The rejection detail page hides the "close" button from agents who aren't leads, and the close endpoint is protected with the lead role. A test closes a rejection as an agent and expects 403.

```diff
src/pages.ts
+  ${isLead(s.user) ? html`<button name="close">Close</button>` : ''}
src/app.ts
+  router.post('/rejections/:id/close', auth.protect(['lead'], closeRejection));
test/close.test.ts
+  test('an agent cannot close a rejection', async () => {
+    const res = await post('/rejections/42/close', { as: 'agent' });
+    assert.equal(res.status, 403);
+  });
```

## What the verdict must say

That hiding the button is a convenience, and the authorization is on the server, tested as the role that mustn't pass: compliant.
