# Bootstrap: an Android app

For an AI coding agent that has completed the [general bootstrap](../../BOOTSTRAP.md), where the Problem Owner described their problem, the [landscape](../../enterprise-architecture/landscape/landscape.md) check is recorded, and an Android app fits ([platforms](../README.md)). The general ground rules still apply.

**Done when** a new project, created from the template, builds, passes `./gradlew check`, and runs its UI tests on a managed emulator.

For a **change to an existing app**, clone its repository, follow its `AGENTS.md`, and do steps 1, 2 and 6 only.

1. **A JDK.** Check `java -version`: JDK 21 is required. If it's missing, install a current OpenJDK 21 build with the operating system's package manager (ask first).
2. **The Android SDK**, command-line tools only, unless the Problem Owner wants Android Studio too. Accepting the SDK licenses (`sdkmanager --licenses`) is the Problem Owner's decision: show them the licenses. Install the platform, build tools and emulator system images for the oldest (Android 12, API 31) and newest Android versions the app will support. The emulator needs hardware virtualization; on Windows, that may need the Problem Owner to enable it in the firmware.
3. **The backend first.** An Android app needs an API. If the landscape check found an existing NATAX API that fits, use it, and ask its owner to accept the app as a consumer ([INT-06](../../enterprise-architecture/principles/integration.md#int-06-dont-break-consumers-and-onboard-them-without-ceremony)). Otherwise, the backend is a second application on the [typescript-web](../typescript-web/BOOTSTRAP.md) platform, with `exposure: staff-edge` and a Technical Owner ([AND-05](standards.md#and-05-the-app-talks-only-to-natax-apis-by-identity-not-by-network)); bootstrap that too.
4. **The repository** (new apps only). Copy [template/](template/) to a new repository, `git init`, and replace the placeholder names. Write the landscape check from your notes into `docs/decisions/0000-landscape-check.md`. Create the Gradle project in it: Kotlin, Compose, `minSdk 31`; the version catalog with only [approved dependencies](approved-dependencies.yaml); dependency locking and verification (`./gradlew --write-verification-metadata sha256 help`, then review and commit `gradle/verification-metadata.xml`); Gradle managed devices for the oldest and newest supported versions; `android:allowBackup="false"`, `dataExtractionRules`, and a network security configuration without cleartext.
5. **No signing keys.** Debug builds use the throwaway debug key. The upload key exists only in the secret store, for the pipeline ([AND-08](standards.md#and-08-reproducible-builds-and-upload-keys-only-the-pipeline-holds)).
6. **Prove it works.** `./gradlew check` and `./gradlew allDevicesCheck` pass (`gradlew.bat` on Windows), and the reports show the tests actually ran. Then write `docs/environment.md` (JDK, SDK and emulator versions, what passed), and continue as the Development Agent.
